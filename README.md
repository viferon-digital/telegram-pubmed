# Сбор постов из Telegram в Google Таблицу (Google Apps Script)

Скрипт складывает посты Telegram-каналов в Google Sheets с дедупликацией,
запоминанием прогресса и запуском по расписанию.

Поддерживаются два независимых режима — их можно использовать вместе.

| | Режим 1: веб-превью `t.me/s/<канал>` | Режим 2: Bot API |
|---|---|---|
| Что нужно | ничего, канал должен быть публичным | бот-администратор канала |
| История канала | да, любая глубина | нет, только новые посты |
| Просмотры | да | нет |
| Файлы медиа | прямые ссылки на CDN | `file_id` (скачивается через `getFile`) |
| Приватные каналы | нет | да |
| Задержка | зависит от триггера (от 1 минуты) | реальное время (вебхук) |

Если канал публичный — начинайте с режима 1, он не требует настройки бота.

## Быстрый старт (режим 1, без бота)

1. Создайте Google Таблицу.
2. `Расширения` → `Apps Script`.
3. Перенесите в проект файлы из папки [`src/`](src):
   `Config.gs`, `Parser.gs`, `Sheet.gs`, `Collector.gs`,
   `BotApi.gs`, `Webhook.gs`, `Triggers.gs`, `Test.gs`.
   Содержимое `appsscript.json` вставьте в манифест
   (`Настройки проекта` → `Показывать файл манифеста appsscript.json`).
4. Запустите в редакторе функцию `collectNewPosts` и подтвердите
   запрошенные разрешения (первый запуск упадёт с сообщением, что каналы
   не заданы, — это нормально, разрешения уже выданы).
5. Обновите вкладку таблицы — появится меню `Telegram`.
6. Меню `Telegram` → `Задать каналы…`, например `durov, meduzalive`.
   Альтернатива: свойство скрипта `CHANNELS`.
7. Меню `Telegram` → `Собрать новые посты`. Появится лист `posts`.
8. Автосбор: меню `Telegram` → `Автосбор каждые 15 минут`
   (или `installTrigger(15)`; допустимые интервалы — 1, 5, 10, 15, 30 минут).

Загрузить архив канала: меню `Telegram` → `Догрузить историю`
(функция `backfillHistory`). Каждый запуск листает `MAX_PAGES` страниц
назад и запоминает, где остановился, — вызывайте повторно или повесьте
ежедневный триггер через `installBackfillTrigger(4)`.

## Настройки

Задаются в `Настройки проекта` → `Свойства скрипта`
(значения по умолчанию — в `src/Config.gs`).

| Свойство | По умолчанию | Назначение |
|---|---|---|
| `CHANNELS` | — | каналы через запятую: `durov, @telegram, https://t.me/meduzalive` |
| `SHEET_NAME` | `posts` | лист для записи |
| `SPREADSHEET_ID` | — | ID таблицы; пусто = таблица, к которой привязан скрипт |
| `MAX_PAGES` | `5` | сколько страниц t.me листать за запуск (≈16–20 постов на странице) |
| `MAX_POSTS_PER_RUN` | `300` | предохранитель по числу постов за запуск |
| `FETCH_DELAY_MS` | `700` | пауза между запросами к t.me |
| `STORE_RAW` | `no` | `yes` — сохранять JSON апдейта Bot API в колонку `raw` |
| `BOT_TOKEN` | — | токен бота (режим 2) |
| `WEBHOOK_SECRET` | — | секрет вебхука, подставляется в URL автоматически |

Текущие настройки можно посмотреть функцией `showConfig()` — токен в логе маскируется.

## Колонки листа

`key`, `collected_at`, `source`, `channel`, `message_id`, `date`, `url`,
`text`, `text_length`, `views`, `media`, `media_urls`, `forwarded_from`,
`forwarded_from_url`, `reply_to`, `link_preview_url`, `link_preview_title`, `raw`.

`key` — это `канал/message_id`; по нему идёт дедупликация,
поэтому повторный запуск не создаёт дублей.

## Режим 2: Bot API

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Добавьте бота администратором в канал.
3. Запишите токен: функция `setBotToken("123456:ABC...")`
   (или свойство скрипта `BOT_TOKEN`). В код токен не вписывайте.
4. Дальше — один из вариантов:

**Опрос по расписанию.** Запускайте `collectViaBot` вручную или триггером.
Скрипт хранит `BOT_UPDATE_OFFSET`, поэтому апдейты не повторяются.

**Вебхук (реальное время).** `Deploy` → `New deployment` → тип `Web app`,
доступ `Anyone`. Затем запустите `setWebhook()` — он возьмёт URL деплоя,
сгенерирует секрет и зарегистрирует вебхук. Проверка — `getWebhookInfo()`,
отключение — `deleteWebhook()`.

Apps Script не отдаёт HTTP-заголовки в `doPost`, поэтому секрет передаётся
в query-строке (`?s=...`), а не заголовком `X-Telegram-Bot-Api-Secret-Token`.

Важно: `getUpdates` и вебхук взаимоисключающи. Если вебхук установлен,
`collectViaBot` вернёт ошибку 409 — сначала вызовите `deleteWebhook()`.

## Проверка парсера

Функция `runParserSelfTest()` разбирает зафиксированный фрагмент разметки
t.me и проверяет поля. В сеть не ходит и в таблицу не пишет — удобно
запускать после правок `Parser.gs` или если Telegram поменял вёрстку.

Те же файлы можно прогнать локально:

```sh
cat src/Parser.gs src/Sheet.gs src/Test.gs > /tmp/run.js
echo 'var Logger={log:function(){}};console.log(runParserSelfTest());' >> /tmp/run.js
node /tmp/run.js
```

## Ограничения

- Веб-превью отдаёт только публичные каналы; у приватных и у каналов
  с отключённым превью страница `t.me/s/...` пустая — скрипт скажет об этом явно.
- Одна страница t.me — примерно 16–20 постов. Глубину за запуск ограничивает
  `MAX_PAGES`, а Apps Script — лимитом в 6 минут на выполнение.
- Ссылки на медиа из CDN Telegram содержат токен и со временем протухают:
  для архива файлы лучше сразу сохранять на Диск.
- Квоты Apps Script: 20 000 запросов `UrlFetchApp` в сутки для обычного
  аккаунта Google. При десятках каналов увеличивайте интервал триггера.
- Реакции в веб-превью не отдаются, поэтому их нет в колонках.
- Служебная разметка t.me может измениться — тогда сначала падает
  `runParserSelfTest()` на нужном поле, чинить надо `Parser.gs`.

## Состояние

Прогресс хранится в свойствах скрипта:
`LAST_ID_<канал>` (самый свежий собранный пост), `OLDEST_ID_<канал>`
(граница докачки истории), `BOT_UPDATE_OFFSET` (offset Bot API).
Функция `resetState()` очищает их, не трогая уже собранные строки.
